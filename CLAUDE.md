# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A from-scratch Minecraft Java Edition server in Go, targeting protocol **763 (1.20.1)**. The author's stated goal is to avoid third-party libraries — prefer writing protocol/NBT/encryption code directly over pulling in `go-mc` or similar. If you need to add a dependency, ask first.

Module name: `minecraft-server` (Go 1.24).

## Build, run, test

```sh
go build ./...           # build everything
go run .                 # build+run, listens on :25565
go test ./...            # tests live in nbt/ and server/ (registry codec)
go vet ./...             # static checks
```

There's no CI, no linter config, no external deps (`go.sum` is empty).

Online-mode auth is toggled via `cfg.OnlineMode` (a `var`) in `cfg/cfg.go`. Online mode hits `sessionserver.mojang.com` (see `mojang/mojang.go`).

Postgres + Redis backends are deployed via `docker-compose.yml`
(`docker compose up -d`) and connected at startup (`connectStores` in
`main.go`). The backend is picked by the **`STORAGE` env var**
(`postgres`, the default, or `memory`): under `postgres` **Postgres is a hard
dependency** — accounts and auth password hashes live there; a failed connect
or migration aborts startup — and bans go to the `bans` table via
`store.BanStore` (a leftover `banlist.json` is imported once by
`importBanlist` and renamed `*.imported`). Under `memory` nothing connects: `Server.Store`/`DB` stay
nil, auth falls back to `memCredStore` (passwords lost on restart), match
history/ratings aren't recorded, bans use `ban.FileStore` on
`BANLIST_FILE` (default `banlist.json`; `off` = RAM only) and ender chests
use `server.FileEnderChestStore` on `ENDERCHEST_FILE` (`enderchests.json`). Redis is
best-effort either way (default on under postgres, off under memory,
`REDIS_ENABLED` overrides): a down Redis logs a warning and the server boots
without it. Handles live on `Server.DB` / `Server.Redis` / `Server.Bans`.

## Architecture

### Connection lifecycle

`main.go` constructs a `*server.Server` (holds the world + entity-ID counter) and spawns `srv.HandleConn` per accepted TCP connection. Each connection has its own `ClientConnection` (in `server/server.go`) referencing the Server, holding the wire conn, state, write mutex, and a `done` channel. After login completes, the connection gains a `*player.Player` (nil before then; only valid in StatePlay).

State machine: `StateHandshake` → `StateStatus` *or* `StateLogin` → `StatePlay`. Defined as a typed enum in `server/state.go`. Dispatch in `processPacket` routes to one of:
- `handler_handshake.go` (`handshake.go`)
- `handler_status.go`
- `handler_login.go`
- `handler_play.go`

Two goroutines per client:
1. **readLoop** (`server.go`) — reads packets with a 30s deadline, dispatches.
2. **keepAlive** (`keep_alive.go`) — every 20s in play state, sends a clientbound KeepAlive.

Both write through `safeWrite`, which is mutex-guarded (`c.writeMu`). The same mutex protects the `c.conn` swap that happens when encryption turns on, since CFB8 stream cipher state would desync under concurrent writes. Cleanup is idempotent (`atomic.CompareAndSwapInt32` on `c.closed`).

### Packet framing

Wire format: `VarInt(length) + VarInt(packetID) + payload`. Helpers in `protocol/`:
- `ReadPacket(conn)` returns the post-length `*bytes.Buffer`.
- `ReadPacketSplit(conn)` returns ID + remaining bytes (used in `handleLogin` for the Encryption Response, which is read directly without going through readLoop).
- `WritePacket(conn, id, payload)` frames and writes; `DebugPackets` gates per-packet logging.
- Three VarInt variants exist because reads happen from `io.Reader` (connection), `*bytes.Buffer` (parsed body), and `[]byte` (raw slice after split).

**Compression is implemented.** `enableCompression` (handler_login.go) sends Set Compression with a 256-byte threshold during login; framing helpers take a `compressionThreshold` parameter (`protocol.CompressionDisabled` before that). Read-side frames are capped at `protocol.MaxPacketLength` (2 MiB) and declared uncompressed sizes at `MaxUncompressedLength` (8 MiB).

### Encryption (online mode)

Flow in `handler_login.go`:
1. `sendEncryptionRequest` — per-connection 4-byte verify token + global RSA public key.
2. `recvAndVerifyEncryptionResponse` — reads response via `ReadPacketSplit`, RSA-decrypts shared secret + verify token, compares token bytes.
3. `mojang.VerifyWithMojang` — POSTs to sessionserver. Mojang requires the "negative bigint hex" hash format (see `mojang/mojang.go`).
4. `enableEncryption` — wraps `c.conn` with `encryption.WrapEncryptedConn` (AES-128 CFB8). Shared secret doubles as AES key and IV. The swap holds `c.writeMu`.
5. `LoginSuccess` sent over the encrypted connection. Properties array count (VarInt 0) is required for both online and offline.

The RSA keypair is process-global, generated in `server.init()` via `NewEncryptionRequest`. Errors panic immediately (not silently dropped).

CFB8 in `encryption/cfb8.go` is a hand-optimized ring-buffer variant. The wrapping `Write` in `encryption/encrypt_connection.go` chunks at 4 KiB and guarantees full writes — **do not collapse to a single `XORKeyStream + Write`**; a partial write desyncs the cipher permanently.

### Games, arenas, matchmaker

Games register a `game.Definition` (ID, Min/Max players, `Template`, `New` Logic factory) in `init()`. `/play <game>` queues via `Matchmaker`; when MinPlayers is reached, `Server.StartGame` clones the Definition's template into a fresh Instance and attaches the Logic.

**Named arenas** are created at runtime: `/arena create <game> <template> [name]` (op). Each game kind that supports arenas registers a `game.ArenaBuilder` (`game/arena.go`); bedwars' is in `games/bedwars/arena_config.go`. The builder takes the loaded map template + the bytes of a sibling JSON config (`<TemplateDir>/<template>.json`, default `schem/templates/...`) and returns a Definition. `CreateArena` then **spins up a running Instance immediately** (id = arena name, auto-named `bw-<n>` for bedwars) via `NewInstance` + `AttachLogic` — one shared world per arena. `Server.arenas` tracks name→kind (cleared in `RemoveInstance`). `/leave` sends a player from a running game to its mode's lobby (`Instance.GameID` — the Definition ID set by `StartGame`, the arena kind set by `CreateArena` — mapped by prefix in `lobbyForGame`: `bedwars…` → BedWars lobby, `ffa…`, `skywars…`; the hub when there's none). `/play <game> <arena>` (and `/instance join <arena>`) `MovePlayer`s the caller into that instance from their own readLoop, so everyone shares one world and is mutually visible. Bedwars' win-check is armed only after ≥2 teams have had members (`engaged`), so a freshly-created empty arena doesn't end itself. (Matchmaker is still used for `/play <game>` with no arena — its `startGame` moves players **sequentially**, since overlapping moves let one player's Respawn wipe another's already-broadcast Spawn.) The arena JSON defines the layout in world coordinates — the map supplies only blocks. Each team carries its own spawn, bed blocks (recoloured to the team via `recolourBed`, which keeps the map bed's facing/part — every bed colour shares one state layout, so a plain default-state swap would leave two "foot" halves), and shop villager NPCs (`teams[].villagers`); generators are a top-level list (per-team or neutral). See `schem/templates/bedwars/badwars_dota_map.json`; regenerate a starter from auto-detect with `GENCFG=1 go test ./games/bedwars -run TestGenSampleConfig`. The BedWars lobby's ender-pearl menu is a live DOTA arena browser (`openBedwarsArenaMenu`/`bedwarsArenaEntries` in `hub_menu.go`): the first slots are one "+ New …" button per mode in `bedwarsModes` (4×4 team game, 1×1 duel; key `create:<kind>` → CreateArena from `templates.BedwarsDotaMap` + join), then one compass per running bedwars arena of either kind that has players, its stack size = the online count.

**BedWars modes.** Bedwars registers two arena kinds (`KindFull`=`bedwars`, `KindDuel`=`bedwars-1x1`, in `games/bedwars/arena_config.go`) over the *same* map + JSON config. The duel builder (`buildBedwarsDuelArenaDef` → `duelConfig`/`selectTeams`) keeps two bases (config indices 0 and n/2 — opposite islands on a ring-ordered 4-team config — or both of a 2-team config), remaps generator team indices, drops the other bases' generators/villagers, and removes their beds (block + block-entity marker) so the map's original-colour beds don't look like a team's; capacity is 2 teams × 1 player. Auto-names are `bw-<n>` / `bw-1x1-<n>`. The JSON config also accepts optional top-level `teamSize` (default 4) and `minPlayers` (default 2) for the full kind. Matchmaker presets live in `defaultModes` (`mode.go`): `bedwars` (4×4 on the DOTA map) and `bedwars-1x1` (2×1 on the generated two-island arena, since the shipped map has 4 beds and `buildSchemArena` requires an exact bed match).

**BedWars gameplay (Hypixel-style).** `OnInstanceStart` turns on `SetPvP` / `SetWeaponDamage` / `SetCustomRespawn` / `SetTNTAutoPrime` and `SetExplosionDamage(0.5)` (TNT/fireballs hurt players half as much); `OnExplosionBreak` (`game.ExplosionBreakVeto`) refuses every bed block, so only a player's dig can destroy a bed. Every player has a **kit** (`kit.go`: armour tier, pickaxe/axe tiers, shears) that `equip` turns into an inventory on join and respawn — wooden sword in hotbar 0, team-dyed leather helmet+chestplate (`Team.Color`), leggings+boots of the tier, tools with Efficiency, shears, plus the team's Sharpened/Reinforced enchants (`teamState.withTeamUpgrades`) and Maniac Miner haste. **Item shop** (`shop_catalog.go` = seven categories with Hypixel prices; `shop.go` = 6-row menu: tabs on row 0 with the selected one glinting, separator row, wares with price/affordability lore; the menu is reopened after each click; a **shift-click** on plain goods buys in bulk — `bulkPurchases`: enough packs to fill one full stack of the item (`world.MaxStackSizeOf`: 64 wool = 4×16, 16 pearls) capped by what the balance affords, never below one, tiered/permanent wares ignore it) — kinds: plain goods (team placeholders `wool`/`terracotta`/`glass` via `resolveGoods`), armour tiers (`kindArmor`, refuses equal/lower), tools (`kindTool`, one slot shows the *next* tier; `replaceTool` swaps in place), permanent shears, enchanted bows/knockback stick, named potions and utilities (`nameBridgeEgg`, `namePopupTower`, `nameSpeedPot`…). **Villager kind** comes from the arena JSON `teams[].villagers[].type` → `Arena.Villagers` keyed by block position (`villagerAt` floors the click's entity X/Y/Z); unknown villagers open the item shop; villagers carry a `world.Entity.Name` label. **Death** (`OnPlayerDeath`, with custom respawn so the core leaves the player dead): killer loots the victim's iron/gold/diamond/emerald, `kit.onDeath` drops tools a tier, inventory wiped, victim spectates 5 s (`respawnDelayTicks`, titles counted down in `processRespawns`) then `Respawn` at the team spawn + `equip`; without a bed it's a FINAL KILL → spectator at `spectatorPos`. Friendly fire is vetoed in `OnPlayerAttack`; the void calls `p.Kill()`. **Team upgrades** (`upgrades.go`, 4-row menu; diamonds): Sharpened Swords, Reinforced Armor I–IV, Maniac Miner I–II, Forge I–IV, Heal Pool, and a 3-deep trap queue (1/2/4 💎). Purchases re-enchant members' existing swords/armour (`applyTeamUpgrades`). **Forge** works on the round's own generator copy (`bedWars.gens` — the `*Arena` is shared by every round): `effectiveIntervalLocked` divides the interval by `forgeMultiplier[tier]` (1.5/2/2/3) and tiers III/IV drop an emerald at the team generator every 60/30 s. **Heal Pool / traps** (`traps.go`) poll from `OnTick`: Regeneration I for members within `baseRadius` (20) of their spawn; the first queued trap fires when an enemy *enters* the radius (edge-triggered via `teamState.inside`): It's a Trap! = Blindness+Slowness 8 s, Counter-Offensive = Speed II + Jump II 15 s to defenders at base, Alarm = strips invisibility + names the intruder, Miner Fatigue 10 s; defenders get a title + dragon growl. **Utility items** (`utility.go`): `OnItemUse` by display name — bridge egg = `ThrowProjectile` laying a 3-wide team-wool deck two blocks under the flight (air only, ≤30 blocks, recorded in `placed`), pop-up tower = 3×3 hollow wool tower with a ladder column, refused if the footprint isn't air; `OnItemConsume` maps the potion names to Speed II / Jump V / Invisibility. **Lobby phase** (`lobby.go`; the DOTA map waits at its JSON `lobby` = (0,73,0) on the glass over the centre fountain — kept by the 1×1 `selectTeams` and read by the auto-detected matchmaker arena too via `configLobby`, the sibling `<map>.json`): a round built with `WithMinPlayers(n > 0)` (every arena/mode definition does — config `minPlayers`, default two full teams = `2×teamSize`, 8 on 4×4; duel 2; the `bedwars` matchmaker preset waits for 8 too) starts in a lobby: joiners fly (`PlayerHandle.SetFlight(true)`, after the Adventure gamemode change that would reset it; turned off at the start) and hold a white wool "Select team" (`team_select.go`): using it opens a one-row menu with each team's wool (picked count / teamSize, the own pick glinting); a pick is a reservation `startRound` honours while the team has room, the rest are dealt onto the smallest teams; leaving drops the pick. Joiners are parked at `Arena.Lobby` (JSON `lobby {x,y,z,yaw}`, default the shared diamond generator's spot, else the first neutral generator, else the spawn centroid) in Adventure with an empty inventory and no team; PvP, building, bed breaking and generators are off (`started=false`), the void teleports back instead of killing, the sidebar shows `Players n/min` + the countdown. At `minPlayers` a 10 s countdown (`lobbyCountdownTicks`, titles each second) runs, cancelled if the count drops; `startRound` deals waiting players onto the smallest teams (sorted by entity id), equips/teleports them, sets `startTick` (the generator timeline clock: `roundTickLocked`) and `engaged`. Late joiners of a running round still get a team at once. Tests/legacy `newBedWars` without `WithMinPlayers` have no lobby.

**Shared generator tiers + sidebar** (`sidebar.go`): diamond/emerald generators follow the Hypixel timeline `genUpgrades` (Diamond II 6:00, Emerald II 12:00, Diamond III 18:00, Emerald III 24:00 of round ticks, i.e. since `startTick`), scaling the configured interval by `genTierSpeed` (¾, ⅖) inside `effectiveIntervalLocked` (which also applies Forge for team generators); upgrades are announced in chat + a pling. Default intervals: iron 40, gold 100, diamond 600, emerald 900 ticks (`defaultGenInterval`; the DOTA JSON matches). `playerStats` (kills / final kills / beds, keyed by entity id, credited in `OnPlayerDeath` / `OnBlockBreak`) feed the per-player sidebar (`sidebarLines`: kills, beds broken, diamond/emerald tier, next upgrade countdown, team), set on join and refreshed every 20 ticks from `OnTick`, cleared on leave. Tests use the slot-addressed `fakePlayer` in `bedwars_test.go` (`slot`, `effect`, `given`, `menuAt`, `buyKey`, `sidebar` helpers).

### Plugins (server-wide)

`game/plugin.go` is the second half of the plugin API. A mini-game's `Logic` is bound to one instance; a **listener** (`game.RegisterListener(name, logic)`, from `init()`) is a `Logic` the server attaches to *every* instance — hub, lobbies, arenas — with that instance's `Ctx`. Each `Instance` snapshots `game.Listeners()` in `NewInstance` (so register before `server.New()`); the core never calls the `Instance.On*` hook fields directly any more but goes through `fireJoin`/`allowBlockBreak`/`filterChat`/… in `server/plugins.go`, which run listeners first (registration order) and the instance's own hook last. Veto hooks (`OnBlockBreak/Place/Interact`, `OnPlayerAttack`) short-circuit on the first `false`; `OnChat` composes rewrites. A panicking listener is logged and counts as "allow".

- **`OnBlockInteract(ctx, p, game.BlockInteraction) bool`** is a new `Logic` hook (NoopLogic allows): every left click (`SbPlayPlayerAction` action 0) and right click (`SbPlayUseItemOnBlock`) on a block, with face + held item, *before* the core treats it as dig / placement / chest open. `false` consumes the click and rolls back the client's prediction; for a consumed survival dig the connection remembers the position (`consumedDig`) so the matching "finished digging" is swallowed too.
- **Plugin commands**: `game.RegisterCommand(&game.Command{Name, Aliases, NeedsOp, Help, Run(ctx, player, args), Complete})`. `lookupCommand` (plugins.go) resolves built-ins first, then plugins (shadowing is logged at boot); plugin commands appear in `/help`, the brigadier tree and tab-complete (`Complete` candidates are prefix-filtered by the server). A `Name` starting with `/` gives a WorldEdit-style double-slash command: the vanilla client sends `//set x` as `/set x`, so `handler_play.go` no longer strips the leading slash and `RunCommand` retries without it for clients that do include one.
- **Bulk blocks**: `game.Instance.SetBlocks([]world.BlockChange)` → `Instance.SetBlocks` (`server/block_bulk.go`) applies to the world and broadcasts one Update Section Blocks (Cb 0x43: section Long, VarInt count, VarLong `state<<12 | x<<8|z<<4|y` per entry — no Suppress Light Updates boolean, 1.20 dropped it) per 16³ section, instead of a Block Update per block.
- **`PlayerHandle.IsOp()`** for permission checks inside hooks (e.g. the wand).
- **`game.ExplosionBreakVeto`** (optional interface on a Logic or listener): `OnExplosionBreak(ctx, igniter, pos) bool` runs for every block an explosion would destroy, *before* the OnBlockBreak chain (`allowExplosionBreakVeto` in plugins.go, wired by `AttachLogic`); `igniter` is nil for an anonymous blast. `game.Instance.SetExplosionDamage(scale)` multiplies explosion player damage per instance (`Instance.ExplosionDamage`, default 1, stored as bits+1 so an explicit 0 survives).
- **`game.ForceStarter`** (optional interface on a Logic): `ForceStart(ctx) error` starts the round now; `AttachLogic` wires it to `Instance.OnForceStart`, which the op command **`/forcestart`** calls in the operator's instance. BedWars sets the countdown to the next tick (the start stays on the tick loop) and marks it `forced`, so a leave doesn't cancel it; it refuses an empty lobby or a running round.
- **`game.PlacementRewriter`** (optional interface on a Logic or listener): `RewritePlacedBlock(ctx, p, pos, blk)` runs before the `OnBlockPlace` veto and the placed block becomes whatever it returns (`rewritePlacedBlock` in plugins.go; `AttachLogic` wires it when the Logic implements it). Beds pass through it as the colour's default state before the foot/head split. BedWars implements it to recolour any placed bed to the placer's team.
- **Entity clicks + GUIs**: `OnEntityInteract(ctx, p, game.EntityInteraction)` fires for a right-click on a world entity (villager NPC, item frame) before the item-frame default; `false` consumes. `PlayerHandle.OpenMenu(title, rows, []game.MenuItem, onClick(game.MenuClick))` shows a chest GUI (`menuKindPlugin` in `hub_menu.go`): `MenuClick` carries the slot plus the vanilla modifiers (`Shift` = Click Container mode 1 "quick move", `Right` = button 1 of mode 0; the server's `menuClick` keeps the raw button/mode pair), and after every click the window is re-sent so ghost pickups are undone and the menu stays open. `CountItem`/`TakeItem` complete the economy surface (`countItem`/`takeItem` in `inventory.go`; take drains the main inventory before the hotbar). BedWars' villager shops (`games/bedwars/shop.go` + `shop_catalog.go`, `upgrades.go`) are built on exactly this — see **BedWars gameplay** below.
- **Sidebar**: `PlayerHandle.SetSidebar(title, lines)` / `ClearSidebar()` (`server/sidebar.go`) is the per-player scoreboard panel on the right: objective `sidebar` in display slot 1, one invisible holder (`§0`..`§e`) + one team (`sb_line_<i>`) per line with the text as the team prefix, scores counting down (the red numbers can't be hidden on 1.20.1). Repeat calls diff against the connection's `sidebar` state and send only changes. **Never create an objective/team the client already has** — that throws client-side and kicks; the client keeps its scoreboard across our two-hop Respawn, so nothing is re-sent in `resyncView`, and `MovePlayer` clears it after the leave hooks. Packet ids (minecraft-data 1.20): Display Objective 0x51, Update Objectives 0x58, Update Teams 0x5A, Update Score 0x5B.
- **Schematic writing**: `schem.FromWorld(world, cornerA, cornerB)` + `(*Schematic).Marshal()`/`schem.SaveFile` emit Sponge v2 gzip NBT; block states round-trip via `world.PaletteName`/`world.StateProperties` (inverse of `ResolveStateID`).

`plugins/worldedit` exercises all of it and is the template for new plugins: one package, `init()` registers a listener + commands, blank import in `main.go`.

### Packet IDs

`server/packet_ids.go` is split into state-scoped const blocks (`Sb*` serverbound, `Cb*` clientbound, with `Handshake`/`Status`/`Login`/`Play` prefixes). Many IDs collide at `0x00` across states; that's correct because dispatch is state-keyed. Source of truth: wiki.vg for protocol 763.

### Play-state join sequence

After LoginSuccess + state transition to play, `sendPlayPackets` (in `server.go`) fires in order:
1. `sendLoginPlay` (Cb 0x28) — includes the registry codec (NBT). Followed immediately by `sendUpdateTags` (Cb 0x6E, `tags.go`) and `sendClearTitles` (Cb 0x0E — the client keeps a title across server switches): the fluid tags `minecraft:water`/`minecraft:lava`, the block tag `minecraft:climbable` and the item tag `minecraft:arrows` (the survival client's bow looks for ammo by that tag; without it bows only drew in creative). **Tags come from the server, not the client** — without them the client renders every fluid as water (its liquid renderer picks lava sprites by the lava *tag*), never counts the player as in water (no swimming), and can't climb ladders. Ids are registry ids (fluid: water 2, flowing_water 1, lava 4, flowing_lava 3; block: ladder 196 …), not block-state ids. Codec is built once via `RegistryCodec()` in `registry.go`, which embeds `registry-codec.json` and converts to NBT through `nbt.FromJSONBytes` with `registryHints`. The hints map encodes per-key NBT type overrides for the 1.20.1 codec; **if the client kicks complaining about a type mismatch, add the offending key to the relevant hint set.**
2. `sendWorldChunks` (Cb 0x24 per column) — bakes the instance world into real chunk data. Every non-air block is bucketed by (chunkX, chunkZ) column + 16-tall section and packed into paletted sections by `chunk.BuildChunkData` (single-valued / indirect 4–8-bit palette / direct 15-bit, 1.16+ non-spanning long packing). Streams the occupied-column bounding box (plus a one-chunk pad) unioned with the spawn ring; empty columns use `chunk.BuildEmptyChunkData`. Heightmaps are still empty (`chunk.BuildEmptyHeightmaps`). Biomes are a single value per column taken from the map: the schematic's dominant biome (`schem` parses `BiomePalette`/`BiomeData`, v2 flat or v3 nested) flows template→world→`BuildChunkData(sections, biomeID)`; `server.BiomeID` resolves the name to its codec registry index (default `minecraft:plains`=39, since biome 0 is badlands). Block entities ARE sent (beds/chests/banners/skulls/… from the world's `BlockEntityProvider`, with empty NBT) so BlockEntityRenderer blocks aren't invisible. Light is full daylight (`writeFullDaylight`). Per-block Block Updates are no longer used for initial world state. Item-frame and other world entities go out separately via `sendWorldEntities` (Spawn Entity 0x01 + metadata).
3. `sendSyncPlayerPosition` (Cb 0x3C) — X/Y/Z + yaw/pitch + flags + teleport ID. Client echoes teleport ID via `SbPlayTeleportConfirm`.

## Gotchas

- **Movement is ignored until the client confirms the server's teleport** (`server/anticheat.go`, like vanilla's `awaitingPositionFromClient`). Every Synchronize Player Position goes through `sendSyncPlayerPosition(x, y, z)` / `sendSetback` (rubber-band, relative rotation so the camera doesn't snap), which take a fresh id from `c.ac.Teleports`; Set Pos / Pos+Rot / Rot packets are dropped while any is unconfirmed. **Never write Cb 0x3C by hand** — an untracked id is never confirmed by anything we wait for, and an id we wait for that never went out freezes the player. Test clients answer like vanilla: `testClient.autoReply` (called from `read`, `startDrain`, `startDiscardDrain`) sends Confirm Teleportation for every 0x3C and Pong for every Ping; a test that moves the player right after a server teleport must wait for that 0x3C first (see `awaitSetback` in `move_validate_test.go`).
- **Anticheat state lives in `c.ac` (`anticheat.State`)**: the player's sprint/sneak input (`c.ac.Sprinting` / `Sneaking`), per-tick history (`Instance.anticheatTick`), Ping/Pong transactions (Cb Ping 0x32 / Sb Pong 0x20, Int32 id, minecraft-data 1.20). `Server.TickTransactions` sends a Ping per player per tick — **on in `main.go`, off in `New()`** because test clients that stop reading would fill the 256-frame send queue and get kicked. Bad packets are `c.flag(check, detail)`-ed (logged, VL kept); a check reaching `anticheat.Threshold` (2.5 = three quick flags) is a detection → `anticheat_punish.go` walks the ladder kick → ban 1d → 3d → 7d → max (ban 1d + ops notified) → max (kick + notify), one step per session (`c.ac.Detected`), every step recorded with its reasons in `Server.AnticheatLog` (`anticheat_status` + `anticheat_punishments` under postgres, `ANTICHEAT_FILE`=`anticheat.json` under memory). **Punishing needs `ANTICHEAT=enforce`** (`Server.AnticheatEnforce`); the default only logs detections. Ops: `/ac info|reset <player>`. **World actions are gated and range-checked** (`server/reach.go`): `mayAct` (alive, not spectator) for attacks / item use / block & entity clicks / drops, `mayBuild` (+ survival or creative) for digging, placing, buckets, TNT; vanilla 1.20.1 ranges — dig eye→block centre ≤ 6, use-on feet→centre < 8, entity eye→hitbox ≤ 6 — and a lag-compensated melee reach (victim `History` from the attacker's last Pong-confirmed tick − 3, closest hitbox + 0.1 within 3.0 survival / 6.0 creative). **Tests that dig/place/attack must put the player within those ranges** (e.g. `digWorld` stands the miner 2 blocks off). Chat and commands go through `acceptChat`: no `§` / control characters / >256 chars (flagged `badpackets.chat`, else players could forge coloured or multi-line system text through `BroadcastChat`), vanilla spam budget (burst 10, then 1/s → kick, ops exempt). Drops (Q, ctrl+Q, window throws) share a 20/s budget (`c.ac.AllowDrop`). A sprint-bonus hit ends the attacker's sprint server-side (`sprintHit`, no KeepSprint). **Movement** (`server/movement.go`): every movement packet (incl. on-ground-only 0x17) feeds the timer balance (`anticheat.Timer`, +50 ms/packet vs wall clock, credit after a teleport confirm); `acceptMove` rejects moves that end in or pass through a `world.FullCube` block (phase → setback). **Nothing trusts the packet's onGround any more**: `serverOnGround()` derives it from `world.Collidable` blocks under the feet — crits need it false *and* a falling last move (`c.ac.Move.LastDY < 0`), and the airborne dig penalty uses it, so **tests that dig need a floor block under the player**. `checkMotion` (survival/adventure only) limits horizontal distance per move (0.75 × Speed + ice + pushes) and rise above the last ground (jump apex + pushes), and flags hovering; **every push the server gives a player must go through `c.giveVelocity(vx, vy, vz)`** after the velocity/explosion packet is queued (knockback, Punch, explosions do) — it budgets the push and Pings, so the Pong marks when the client applied it. Setbacks (`sendSetback`) are marked in `Teleports` and don't reset the air state; real teleports do. **Tests that move a survival/adventure player must move at walking pace** (≤ 0.75/packet, stay on a floor) or switch to creative. Action heuristics (`server/actions.go`): survival digs have a 20/s budget and must be in front of the view (60°, unless within 2 blocks); placements a 12/s budget, a cursor in [0,1] and a clicked face that faces the eyes; attacks a 20/s budget, an arm swing after each (vanilla sends Swing right after Interact, before the tick's movement packet) and a view ray through the victim's hitbox (+1.0); a Pong-confirmed push must move the player along it (`checkKnock`). Action checks accept the current or the previous pose (`MoveState.PrevFeet/PrevYaw/PrevPitch`). **Tests that attack use the `attack` helper** (aims, attacks, swings); `attackRaw` is the bare packet. **`/fly [player]`** (op, `server/fly.go`) grants "may fly" through Player Abilities (Cb 0x34: flags + fly speed + FOV modifier, verified against minecraft-data); `checkMotion` skips a player while `flightExempt()` (on, or off but not yet Pong-confirmed); every gamemode change (`sendGameModeChange`) and Respawn (`sendRespawn`, so any instance move) drops it, as the client resets its abilities there. A client claiming flight (Sb Player Abilities 0x02) without permission outside creative/spectator is flagged `badpackets.abilities`. Tests that send forged packets on purpose (`barrier`) are fine because `New()` doesn't enforce; a packet flood (`anticheat.PacketRate`/`PacketBurst`) or `MaxOutstanding` unanswered Pings kicks. `MovePlayer` calls `c.ac.Reset()` (history + transaction epoch belong to the old instance).
- **`handleLogin` reads from `c.conn` directly** for the Encryption Response while `readLoop` is parked in `processPacket`. Works only because both run on the same goroutine — don't introduce concurrent reads.
- **Bans go through `Server.Bans` (`ban.Store`)**, never a package global: `IsBanned(ctx, name)` in the login handler, `Add`/`Remove` in `/ban` `/unban`. `server.New()` installs `ban.NewMemoryStore()` (what tests see); `main.connectStores` swaps in `store.BanStore` (Postgres, keyed by player row — banning a never-seen name creates the row with its offline UUID) or `ban.FileStore` (banlist.json, rewritten on every change). A failing lookup at login fails **open** with a warning. Expired entries are filtered at lookup in every backend.
- **`OfflineUUID`** (`protocol/uuid.go`) uses vanilla `MD5("OfflinePlayer:" + name)` with v3 UUID bits — match this exactly if reproducing behavior.
- **Registry codec type hints (`server/registry.go`) are best-effort.** If the client disconnects right after LoginSuccess complaining about a wrong type, add the key to ByteKeys/FloatKeys/DoubleKeys/LongKeys.
- **Light data is a full level-15 sky-light for every section** (`writeFullDaylight` in `play_send.go`): all 26 light sections (24 + 2 padding) get a 2048-byte 0xFF sky array, block light zero. This forces permanent daylight with no dark chunks. The server never sends Update Time, so the client stays at its default day time and never cycles to night — that's what keeps the bright sky-light rendering as day. If you ever add a day/night cycle, sky light alone will darken at night.
- **Chunk baking holds the whole occupied region in memory per join.** `sendWorldChunks` ranges the (sparse) instance world once and allocates a `[4096]int32` per occupied section. Fine for current map sizes; a streaming/per-chunk-on-demand approach is the future step if maps get much larger or view distance grows.
- **Throwable items** (`projectile.go`): using egg / snowball / ender_pearl (right-click in air, `SbPlayUseItem`) spawns a projectile entity simulated on the instance tick loop (gravity, drag, crude non-air-block collision). On impact an ender pearl teleports its thrower to the landing spot; egg/snowball just despawn. Dispatch keys off the held stack in the server-side inventory model; the server-given menu items (navigator rod, lobby arena-selector pearl) are recognised by their custom `itemStack.Name` (`navigatorName`/`selectorName`) wherever the player moved them, so a plain ender pearl is thrown while the selector opens a menu. No item consumption.
- **The inventory model (`c.inv`, `inventory.go`) is authoritative and persists across instances/respawns.** Hotbar fills first (`giveSlotOrder`), existing stacks top up to 64. **Container clicks are simulated server-side** (`click.go`, a port of vanilla 1.20.1 `AbstractContainerMenu.doClick`: pickup/right-split, shift-click via `quickMoveStack` for window 0 and chests, number-key/F swap, clone (creative only), Q throw, drag-click `dragState` across packets, double-click gather; armor slots take only their piece, max 1). The client's changed-slots + carried item are its *prediction*, parsed by `readClickClaim` and only compared (`clickClaim.matches`) — a mismatch re-sends the window, nothing from the packet is ever stored, so neither counts nor item NBT/enchantments can be forged. The 2×2 crafting result never yields (crafting isn't modelled) and closing window 0 hands the grid back (`returnCraftGrid`). Spectators' clicks only resync. `TestClickNeverCreatesItems` fuzzes the invariant "outside creative, clicks never change the item total"; container windows (menus, chests, plugin GUIs) mirror the real inventory from the model (`writeInventoryMirror`) instead of faking the hotbar, and closing a menu / `resyncView` / `MovePlayer` re-send the whole window 0 (`sendInventoryContents`). Hub UI items are real named stacks in the model; `MovePlayer` strips them (`stripNavigatorItems`) when the target is neither hub nor lobby, and hub/lobby joins hand them out again. **Landing in the hub or a lobby resets the player** (`resetForHub`, before the Respawn packet so it carries the gamemode): revived if dead, full health, no absorption/effects/fire, empty inventory, gamemode back to Adventure (a creative op keeps Creative) — so a finished game's spectator mode and kit never leak into the hub. The cursor stack is tracked too (`c.cursor`, the simulation's carried item; Set Container Content sends it). **Drops become item entities** (`drop.go`): Q / ctrl+Q (Player Action 4 / 3) throw one unit / the held stack via `Instance.ThrowItem` (eye height, look direction, vanilla 0.3 speed, no pickup for `itemThrowDelay`=40 ticks, so the thrower can't vacuum it back); inside window 0 and chest windows the click simulation throws what a click-outside-the-window or the drop key over a slot releases (`clickView.drops` → `throwAll`); closing any window with a stack on the cursor throws it (`dropCursor`). Hub UI items (navigator/selector) refuse to drop. Item entities now carry horizontal velocity (`slideItem`: air drag, ground friction, stop against solid blocks, fall off edges).
- **Survival digging is timed and tool-gated** (`server/dig.go`, tables in `world/breaking.go`). "Started digging" breaks at once only in creative (no drop) or for hardness-0 blocks; otherwise the server records `digPos`/`digStartTick` and "finished digging" is accepted only once `≥ 70%` of `world.BreakTicks(BreakInfoFor(block), heldItem)` has elapsed (vanilla formula: tool speed / hardness / 30, or / 100 when the tool can't harvest), else the block is replayed. A break drops the block's item (`world.BlockDrop`: cobblestone for stone, nothing for glass/leaves, ores → raw/gem) as an item entity only if `world.CanHarvest` (tool class + tier for `RequiresTool` blocks: obsidian needs a diamond pickaxe, terracotta/end stone any pickaxe, wool/planks bare hands). Nothing drops when the game's `OnBlockBreak` hook already cleared the block (BedWars beds). A bed half removes its partner (`bedPartner` from the state's facing/part) and drops one bed. Hardness lookup is exact name → suffix/contains patterns → default 1.0; extend `exactBreakInfo`/`patternBreakInfo` for new blocks. The full formula (`world.BreakTicksWith` + `world.DigContext`) also applies **Efficiency** (tool NBT), **Haste / Mining Fatigue** (potion effects), **Aqua Affinity** (helmet NBT), the ÷5 penalties for a submerged head (eye block is water) and for being airborne (`Snapshot.OnGround`). Sources are pluggable on the Server (`server/modifiers.go`): `Server.Enchantments` (default `nbtEnchantments`: levels parsed from the item's `Enchantments` NBT list — `itemStack` now round-trips `Damage` + `Enchantments` + display name through `readSlot`/`writeStack`) and `Server.Effects` (default `effectTable`: timed per-connection effects — speed, slowness, haste, mining_fatigue, jump_boost, regeneration, invisibility, blindness, absorption with vanilla ids — granted by the op command `/effect <player> <effect> [level] [seconds]` / `clear` or by games through `applyEffect`/`removeEffect`/`clearEffects`/`activeEffects`/`effectLevel` on the connection; sent as Entity Effect 0x6C / Remove Entity Effect 0x3F, re-sent in `resyncView` (Respawn drops them), cleared in `fireDeath`, forgotten on disconnect). **Speed / Slowness also need `sendMovementAttributes`** (`server/attributes.go`): the 1.20.1 client only draws the icon from Entity Effect; the actual speed is the `generic.movement_speed` attribute with vanilla's modifier UUIDs (plus the sprint boost while sprinting, since Update Attributes replaces every modifier the client holds), synced on apply/remove/expiry and after Respawn. `effectsTick` sweeps expiries every 20 ticks and heals Regeneration (1 HP per 50 ticks, halved per level). **Absorption** (`server/absorption.go`) is a pool on `player.Player` (`Absorption`/`SetAbsorption`, 4 HP per level, re-apply never shrinks it) that `ApplyDamage` drains before health; the client renders it only from Player metadata index 15 ("Additional Hearts", Float), not from the Entity Effect packet, so `syncAbsorption` broadcasts that field whenever the value changes — it is called from `sendSetHealth` (every damage path already syncs health), from the effect's grant/removal/expiry, and forced from `resendEffects` after a Respawn; death and `Respawn()` zero it. Invisibility flips entity-flag 0x20; the flag byte is built by `entityFlags()` (fire 0x01 | invisible 0x20) and broadcast by `broadcastEntityFlags`. **Tool durability**: `damageHeldTool` adds 1 per non-instant block (swords 2) and on landed hits (swords 1, other tools 2); `world.ToolDurability` caps per material (gold 32 … netherite 2031, shears 238); Unbreaking spares wear with probability lvl/(lvl+1); at the cap the slot empties and the item-break sound plays. **Placement orientation** (`server/orient.go`, `orientForPlacement`): blocks that must attach get their state from the clicked face + the placer's yaw; today ladders (`world.Ladder`, states 4654..4661) hang on the clicked wall, else on the first solid wall around the spot starting from the one the player faces, and are rejected with no wall. Extend the switch for other facing blocks. **Placement can't overlap a player**: `Instance.blockedByPlayer` (0.6×1.8 hitbox, spectators ignored) rejects the target block (both halves for beds) and rolls the client back.
- **Fluids flow** (`server/fluid.go`): water (every 5 ticks, thins by 1, reach 7) and lava (every 30 ticks, thins by 2, reach 3) are blocks whose state encodes `level` (0 source, 1..7 flowing, 8 falling). Nothing flows at map load; `Instance.SetBlock`/`SetBlocks` schedule the changed position + 6 neighbours (`scheduleFluid`) and `fluidTick` re-evaluates due ones like vanilla's `FlowingFluid.tick`: derive the level from neighbours (drain when unfed; two adjacent water sources over solid ground make a new source), then spread down (falling) and sideways (sources always, flowing only when not over a hole) into air or thinner same fluid. Water and lava don't interact. **Buckets** (`server/bucket.go`): the vanilla client sends a plain Use Item for a bucket (no target block), so the server ray-casts from the eyes along the look vector (5 blocks): a filled bucket passes through fluids, stops at the first solid block and sets a source of its fluid in the block in front of it (through `allowBlockPlace`); an empty bucket scoops the first fluid *source* on the ray (through `allowBlockBreak`). Survival swaps the held bucket (`swapHeld`), creative keeps it. Without this the client's own prediction showed a bogus fluid that the server never had. Fluids are `Unbreakable` in the hardness table and `startDig`/`finishDig` replay them in every gamemode. `burnTick` hurts non-creative players whose feet or head block is lava (4 HP / 10 ticks via `hurtEnvironment`, gated on the instance's combat switch so lobbies stay safe) and sets them on fire for 300 ticks (`ClientConnection.fireTicks`): out of the lava they keep taking 1 HP / 20 ticks until the fire runs down, water (feet or head) extinguishes it, death clears it, and the on-fire entity flag (metadata index 0, bit 0x01, `entityFlagsPayload`) is broadcast on each transition so everyone — including the burning player's own client — sees the flames.
- **Weapon damage & armor** (`world/combat_items.go`, `server/armor.go`): with `Instance.SetWeaponDamage(true)` a hit's base damage is `world.AttackDamage(held)` + Sharpness (0.5·lvl+0.5) instead of `Combat.BaseDamage` (off by default: FFA/hub unchanged). Every damage source (melee, lava/fire, explosions, arrows) passes through `absorbDamage`: vanilla armor formula over slots 5..8 (`ArmorPoints`), Protection EPF, then each worn piece wears max(1, dmg/4) (Unbreaking may spare it; break → slot emptied, break sound, equipment rebroadcast). Knockback enchant adds 0.5·lvl horizontal launch. Armor durability lives in `ToolDurability`.
- **Custom respawn** (`die()`): with `Instance.SetCustomRespawn(true)` a death only extinguishes, clears effects, plays the sound and fires `fireDeath`; the player stays Dead (no Combat Death screen / Set Health 0 / teleport) until the game calls the PlayerHandle Respawn.
- **Timed consumables** (`server/consume.go`): Use Item with a golden apple / potion stores a `useState` on the connection; `Instance.consumeTick` finishes it after 32 ticks if the same slot+item is still held (slot change, dig start, death or Player Action 5 cancel). `fireItemConsume` gives the game first refusal, else vanilla: golden apple = Regeneration II 5 s + Absorption I 2 min (no direct heal, like vanilla), potion → effect from its `Potion` NBT id (`potionEffect`: swiftness/leaping/invisibility/regeneration/slowness variants) leaving a glass bottle. Use Item first runs `allowItemUse` (game.ItemUse hook); then consumables, bow draw, fire charge (fireball), buckets, throwables — ender pearls and fire charges are consumed in survival. **A fire charge used on a block** (Use Item On Block, which is what the client sends whenever a block is in reach — e.g. looking at your own feet) is the same fireball throw unless the block is TNT (`tryIgniteTNT`): the handler rolls back the fire the client predicted on the clicked face, runs `allowItemUse`, launches and consumes.
- **Projectiles** (`server/projectile.go`): `launch(p, speed)` is the shared spawner; per-projectile gravity/drag/noGravity/maxTicks/data; `stepProjectiles` moves everything under `projMu` and returns landed ones whose `impact` (pearl teleport, fireball `explodeWith` power 1.5 × knockback 1.5, arrow hit, game `onImpact`) runs after the lock is released; `onTick` hook can end a flight. **Arrows** (`server/arrow.go`): bow draw via `useState.bow` (the draw/eat pose goes to the other players as living-entity metadata index 8 via `broadcastHandState`, never to the user's own client), release on Player Action 5 with force (t²+2t)/3, speed 3·f, gravity 0.05, Spawn Entity data = the shooter's entity id (1.17+ owner semantics, no +1) and yaw/pitch from the velocity (`projectileAngles`) in spawn + teleports, per-tick segment-vs-hitbox test (shooter/dead/spectators skipped, `allowAttack` veto honoured), block collision by ray-marching the whole step (`marchSolid`, 0.1-block samples — a 3-block/tick arrow would otherwise tunnel through a thin wall) with the arrow parked at the last free point before the face, damage ceil(speed·(2+Power bonus)) ×1.5 on full draw, Punch 0.6·lvl shove, one arrow consumed (creative exempt; **Infinity** keeps it but still needs one in the quiver), arrows stick in blocks for 60 s and are **picked up** by a player walking into them (`pickupCandidate`, the item-pickup box): a plain survival shot returns the arrow (`giveItem`, refused when full), a creative/Infinity shot is creative-only and gives nothing — `projectile.pickup`, Pickup Item 0x67 + Remove Entities.
- **Named world entities**: `world.Entity.Name` (e.g. "§bITEM SHOP") is sent as always-visible custom-name metadata (index 2 OptChat + index 3 true) by `frameMetadataPayload`, which now serves every world entity, not just item frames.
- **Placement extras**: `Instance.SetTNTAutoPrime(true)` primes a placed TNT block at once (`tntAutoFuse` 50 ticks); a placed sponge soaks connected water within 7 blocks (≤65, `absorbWater`) and becomes a wet sponge. Team-colour terracotta and stained glass blocks are registered in `world/block.go`.
- **Titles** (`server/title.go`): `sendTitle(title, subtitle, fadeIn, stay, fadeOut)` / `Instance.broadcastTitle` send Set Title Animation Times (0x60) → Set Subtitle Text (0x5D) → Set Title Text (0x5F); non-positive times fall back to vanilla 10/70/20.
- **Equipment is visible to others** (`server/equipment.go`): Set Equipment (Cb 0x55) with all six slots is built from the inventory model (`equipmentPayload`: hotbar+heldSlot, off hand 45, armor 5..8, via `writeStack` so NBT shows) and broadcast by `equipmentChanged()` — call it after any change to the held slot/stack, armor or off hand (already wired: held-slot packet, window-0 clicks, consumeHeld, swapHeld, dropHeld, damageHeldTool). Joining/resyncing clients get everyone's gear right after Spawn Player (`sendOthersEquipment`), and the newcomer's gear is broadcast next to their Spawn Player.
- **Dropped items are real entities** (`server/item_entity.go`): `Instance.DropItem` (exposed to games via `game.Instance.DropItem` / `DroppedItemsNear`) spawns a `minecraft:item` entity (type 54) that hops, falls onto the block below, merges with a same-item drop within one block (up to a 64 stack), is collected by the first living non-spectator player whose vanilla-sized pickup box contains it (`giveItem` returns the overflow, which stays on the ground), and despawns after 5 minutes. Pickup broadcasts `CbPlayPickupItem` (0x67) for the fly-in animation. They're re-streamed on join/respawn through `sendWorldEntities`. BedWars generators use this by default (`dropGranter`): the resource appears at the generator's block from the arena JSON, and the pile is capped per generator (`maxStack` in JSON, default iron 48 / gold 16 / diamond 8 / emerald 4). `inventoryGranter` (straight to inventory) is still available via `WithGranter`. **Floating text** (`server/hologram.go`, `game.Instance.SpawnHologram` → `game.Hologram{SetText,Remove}`) is an invisible small marker armor stand (type 2) with an always-visible custom name (§-codes work), no gravity; re-streamed on join/respawn like items. BedWars puts a two-line countdown (`games/bedwars/hologram.go`: resource title + "Spawns in Ns" / "Full") over every diamond/emerald generator — `hologramHeight` blocks above the generator block, from the map JSON (default 2; like `lobby` it's a map-wide setting: `applyMapSettings`, kept by `selectTeams`, read by the auto-detected arena via `siblingConfig`), refreshed from `OnTick`.
- **TNT is vanilla-shaped** (`server/tnt.go`): flint and steel / fire charge on a `minecraft:tnt` block (or another explosion) swaps it for a primed TNT entity (type 101, fuse metadata index 8) simulated on `tntTick`; at fuse 0 `explode` ray-marches the 16³ shell with `world.BlastResistance`, runs every destroyed block through the `ExplosionBreakVeto` hook and then the OnBlockBreak veto chain with the igniter as actor (so hub/BedWars rules hold; a nil actor is allowed on hook panic), hurts players **before** the blocks are cleared (exposure is cast through the intact world, so a wall shelters), drops items with chance 1/power, re-primes caught TNT with a 10..29 fuse, and damages/knocks back players via per-player Explosion (0x1D) packets (combat-gated, creative/spectator immune, damage × `Instance.ExplosionDamage()`). The client plays the sound/particles itself from that packet.
- **Chests have a stored inventory** (`chest.go`): right-clicking a chest block opens a 9×3 GUI streamed from a `chestStore` — `blockChest` over `Instance.chests[pos]` for regular chests, or the player's `enderChest` (one record per player UUID on `Server.enderChests`, shared by every ender chest block in every instance; loaded on first open and saved after every click through `Server.EnderChests` — `store.EnderChestRepo`/`ender_chests` table under postgres, `FileEnderChestStore` on `ENDERCHEST_FILE` under memory, see `ender_persist.go`) — 27 `itemStack`s, no item NBT modelled. Clicks are simulated over chest + player inventory (`clickChest`) inside `chestStore.update`, the store's lock, so two players can't both take one stack (other viewers aren't live-updated). `nbt.SkipTag` lets the slot reader skip item NBT it doesn't store. The chest GUI reuses the single menu window (`openMenu{kind:"chest", chestPos}`).
- **`sendRespawn` sends TWO Respawn packets (the_end → overworld).** A same-dimension Respawn leaves ghost entities/blocks on the client; the vanilla client only does a full unload+reload when the dimension actually changes, so we hop through `the_end` first. `resyncView` (`resync.go`) is the reusable "clear everything the client sees + re-stream" primitive (Respawn → chunks → world entities → tab list + other players + own HP/attributes); `MovePlayer` (cross-instance) and combat `respawn` (in-place) both go through this so transitions don't leave ghosts. Anything depending on a single Respawn packet (e.g. test packet-sequence assertions) must account for the pair.

## Conventions

- Comments and log messages are a mix of Russian and English — match the surrounding file's language.
- Errors wrap with `%w` and use a noun-phrase prefix (`"reading packet ID: %w"`).
- File names are `snake_case.go`. Handlers are `handler_<state>.go`. Per-direction play helpers are `play_read.go` / `play_send.go`.
- No structured logging — everything is `fmt.Printf`. Per-packet write logging is gated behind `protocol.DebugPackets = true`.
