# Anticheat: аудит и план

Состояние на 2026-10-28 (коммит `b562012`). Сервер почти полностью доверяет
клиенту: валидируются только NaN/Inf и «>10 блоков за пакет» в движении
(`server/move_validate.go`) и время копания (`server/dig.go`). Ниже — найденные
дыры по приоритету, затем общий план.

Уровни: **P0** — эксплойт ломает экономику/игру или кладёт сервер, делается
модифицированным клиентом за минуты; **P1** — явный чит-функционал (reach,
nuker, fly); **P2** — эвристики и полировка.

## P0 — критично

### 1. ~~Set Creative Slot принимается в любом режиме~~ — исправлено
`server/handler_play.go:481` → `onSetCreativeSlot` (`server/inventory.go:158`)
пишет предмет в модель без проверки gamemode.

- **Эксплойт:** в survival/adventure отправить `SbPlaySetCreativeSlot` с
  64 алмазами/изумрудами → покупки в магазине BedWars бесплатны; любой
  предмет (TNT, обсидиан, незеритовый меч) из воздуха.
- **Фикс:** игнорировать (и считать нарушением), если `c.gamemode() != Creative`.
  Дополнительно — валидировать слот (`-1` = drop, `1..45`) и `Count` 1..maxStack.
- **Сделано:** `onSetCreativeSlot` — вне creative флаг `inventory.creative`
  + слот пересылается из модели; слот вне 1..45 и стек больше максимума —
  флаг `badpackets.creativeslot`. Тесты: `server/exploit_fixes_test.go`.

### 2. ~~Клики инвентаря/сундуков доверяют массиву «changed slots»~~ — исправлено
`applyInventoryClick` (`server/inventory.go:119`), `applyChestClick`
(`server/chest.go:382`). Сервер записывает в модель то, что клиент назвал
новым содержимым слотов. `dropDeficit` ловит только *уменьшение* суммы —
увеличение принимается.

- **Эксплойт:** один Click Container с `changed slots = [{36: diamond×64}]` —
  алмазы появились. Через сундук — то же, плюс предмет сохраняется в
  эндер-сундук (Postgres) → дюп переживает рестарт.
- **Фикс:** серверная симуляция клика по `slot/button/mode` (0 pickup,
  1 quick-move, 2 hotbar swap, 3 middle-click (только creative), 4 drop,
  5 drag, 6 double-click) над моделью `inv + cursor (+ chest)`; результат
  сравнивается с массивом клиента, при расхождении — полный ресинк
  (`sendInventoryContents` / `sendChestInventory`). Минимальный промежуточный
  шаг: инвариант «суммы предметов по id не растут» (`itemTotals` до/после) —
  при росте откат и ресинк. Это закрывает генерацию предметов почти без кода.
  Также проверять State ID (сейчас читается и выбрасывается, `handler_play.go:492`).
- **Сделано:** сразу полная симуляция (`server/click.go`, порт vanilla
  `doClick` 1.20.1: все режимы 0–6, drag между пакетами, shift-click по
  `quickMoveStack` для инвентаря и сундука, слоты брони, F/цифры). Ответ
  клиента только сравнивается, при расхождении — ресинк окна. Сундук
  меняется под локом хранилища. Fuzz-тест `TestClickNeverCreatesItems`:
  вне creative сумма предметов (слоты + курсор + выброшенное) не меняется.
  State ID не нужен — сервер всё равно авторитетен. Крафт 2×2 отключён
  (результат не выдаётся), сетка возвращается в инвентарь при закрытии.

### 3. ~~Чары и NBT предметов берутся от клиента~~ — исправлено
`readSlot` (`server/chest.go:416`) парсит `Enchantments`/`Damage` из NBT
клиента, а `heldEnchant` использует их в бою (`server/combat.go` Sharpness,
Knockback, Protection в `armor.go`, Efficiency в копании).

- **Эксплойт:** вместе с п.1/п.2 — меч с Sharpness 32767 (one-shot), броня
  Protection 1000, кирка Efficiency 255 (мгновенное копание обсидиана).
  Даже с честной симуляцией кликов NBT нельзя брать из пакета: сервер должен
  переносить *свой* стек, а не тот, что прислал клиент.
- **Фикс:** при симуляции кликов (п.2) стеки берутся только из модели;
  данные от клиента — лишь для сравнения. В creative — ограничить уровни
  чар (например ≤ 10) и `Count`.
- **Сделано:** закрыто симуляцией п.2 — NBT из Click Container не хранится
  нигде. Единственный вход клиентского NBT — Set Creative Slot, и он теперь
  только в creative (п.1); `/gamemode` — команда опа, поэтому чары в
  creative не ограничивались.

### 4. ~~Respawn без смерти~~ — исправлено
`server/handler_play.go:399` → `respawn()` (`server/combat.go:238`) не
проверяет `IsDead()`.

- **Эксплойт:** Client Command action 0 в любой момент → полное HP +
  телепорт на спавн (побег из боя с хилом). В BedWars (custom respawn)
  мёртвый игрок пропускает 5 с спектатора, а после FINAL KILL — возвращается
  в игру живым.
- **Фикс:** `if !c.player.IsDead() || c.instance.CustomRespawn() { return }`.
- **Сделано:** ровно так, в обработчике Client Command; флаг
  `badpackets.respawn`.

### 5. ~~NBT-бомба: аллокация по длине из пакета~~ — исправлено
`nbt/unmarshal.go:139,162,181,198,219` — `make(..., n)` с `n` до 2³¹−1 из
4 байт пакета. Вызывается на каждый слот в Click Container / Creative Slot.

- **Эксплойт:** 10-байтный тег `ByteArray len=0x7FFFFFFF` → попытка выделить
  2 ГБ; `List` с длиной 2³¹ → 32 ГБ. Go-OOM — фатальная ошибка, `recover` не
  поможет: **падает весь сервер**. Плюс нет лимита глубины вложенности.
- **Фикс:** перед `make` проверять `n <= r.Len()` (для списков —
  `n*minElemSize <= r.Len()`), лимит глубины (vanilla — 512) и общего
  размера. Это защита, а не античит, но чинить первой.
- **Сделано:** `nbt/unmarshal.go` — длины проверяются против остатка входа
  до `make`, глубина ≤ `MaxDepth` (512), сетевой NBT (`SkipTag`,
  `UnmarshalNetwork` в `readSlot`) декодируется под квотой `NetworkQuota`
  (2 MiB, учёт по мотивам vanilla `NbtAccounter`). Файлы (`Unmarshal`,
  схематики) — без квоты. Тесты: `nbt/limits_test.go`.

### 6. ~~Установка блока поверх существующего~~ — исправлено
`server/handler_play.go:270` — `SetBlock(placePos, block)` без проверки, что
`placePos` — воздух/заменяемый блок. BedWars `OnBlockPlace` помечает позицию
как `placed` (`games/bedwars/bedwars.go:374`), после чего она ломаема.

- **Эксплойт:** Use Item On Block с координатой рядом с вражеской кроватью /
  блоком карты → блок карты заменён шерстью и стал ломаемым; потенциально
  уничтожение половины кровати без копания.
- **Фикс:** разрешать только при `Air` / жидкости / заменяемых (трава, снег
  слоем); иначе откат через `sendBlockUpdate`.
- **Сделано:** `world.Replaceable` (воздух, вода/лава, трава, папоротник,
  мёртвый куст, лоза, огонь…; двойные растения и снег — нет). Проверка в
  Use Item On Block и для обеих половин кровати. Без флага: vanilla-клиент
  попадает сюда при рассинхроне. Заодно клик по траве ставит блок на её
  место (`world.ReplacedInPlace`), как в vanilla.

    это измерение, а не невозможный пакет).

### 9. Движение: fly / speed / nofall / timer
`move_validate.go` пропускает всё до 10 блоков за пакет; `SbPlayPlayerAbilities`
(`handler_play.go:370`) игнорируется, но и не нужен клиенту для полёта —
он просто шлёт позиции. `OnGround` клиента используется в критах
(`combat.go`: `crit := !aSnap.OnGround`) и в скорости копания.

- **Эксплойт:** fly, speed ×5, телепорт до 10 блоков/пакет, phase сквозь
  стены, «криты» на каждом ударе (`onGround=false` на земле), nofall (урона
  от падения пока нет — станет актуально, когда появится).
- **Фикс (поэтапно):**
  1. Горизонтальная скорость: лимит на дельту за тик по `movement_speed`
     (с учётом Speed, спринта, нокбека, льда) с буфером нарушений → setback.
  2. Вертикаль: в воздухе Δy должна убывать по `(vy − 0.08)·0.98`; прыжок
     ≤ 0.42 (+0.1·Jump Boost); держать «бюджет» после нокбека/взрыва/пёрла.
  3. `onGround` — пересчитывать серверно (есть ли твёрдый блок под хитбоксом),
     не верить клиенту в критах и `digContext`.
  4. Timer: баланс «тиков» — пакетов движения не больше ~20/с в среднем
     (окно 1 с, допуск на лаг-спайки).
  5. Phase: луч от старой позиции к новой не должен проходить сквозь
     твёрдые блоки (`marchSolid` из `arrow.go` пригоден).
  - После серверного телепорта игнорировать движение до `TeleportConfirm`
    с нужным id (сейчас confirm — no-op, `handler_play.go:118`).
- **Этап 1 сделан** (`server/movement.go`, `anticheat/timer.go`,
  `world/collision.go`):
  - **timer** — баланс пакетов движения (Set Pos / Pos+Rot / Rot и
    on-ground-only 0x17) против реального времени: +50 мс за пакет, минус
    прошедшее; запас простоя ≤ 1 с, допуск 150 мс; пакет после
    подтверждения телепорта прощается. Флаг `movement.timer` (порог 5).
  - **phase** — конец хода не может пересекать полный блок, путь (с
    сжатым на 0.2 хитбоксом, чтобы не ловить срезанные углы) — тоже;
    иначе откат + флаг `movement.phase` (порог 5). Застрявший внутри блока
    может выйти, spectator проходит сквозь стены. «Полный блок» — белый
    список (`world.FullCube`), чтобы плиты/ступени/заборы не давали ложных
    срабатываний.
  - **земля на сервере** — `serverOnGround()` по блокам под ногами
    (`world.Collidable`, наоборот, всё, что держит). Криты теперь требуют
    серверного «в воздухе» и падения; штраф копания в воздухе — тоже
    серверный. Флаг onGround из пакета больше ни на что не влияет.
- **Этап 2 сделан** (`server/movement.go` `checkMotion`,
  `anticheat/velocity.go`):
  - **бюджет толчков** — нокбек, Punch, взрывы (файрбол-джампы) пишутся в
    `Velocity` и сопровождаются Ping'ом; до Pong импульс засчитывается
    целиком, после — горизонталь затухает ×0.91 за ход, вертикаль живёт до
    приземления;
  - **speed** — горизонталь за ход ≤ 0.75 × (1 + 0.2·Speed) + толчки
    (+1.0 лёд / +1.6 синий лёд 2 с после него); избыток копится в буфере
    (> 0.3 → откат + флаг `movement.speed`);
  - **fly** — подъём над последней опорой ≤ апекс прыжка (с Jump Boost) +
    апекс толчков + 0.2; зависание/планирование (после 15 ходов в воздухе
    не падает, после 30 — падает медленнее 0.3/ход, 10 ходов подряд) → откат
    + флаг `movement.fly`;
  - исключения: creative/spectator, жидкости, лестницы/лозы/леса/паутина/
    мёд/порошковый снег рядом, 3 с после слизи или кровати; закончившийся
    Speed/Jump учитывается ещё 2 с. Откат не «приземляет» (иначе fly-чит
    обнулялся бы каждым откатом), настоящий телепорт — да. Подошва для
    «земли» расширена на 0.03 (sneak-бридж на краю блока).
  - Пороги детекта speed/fly — 5. Не покрыто: «спринт назад»/omnisprint,
    nofall (урона от падения нет), step-хак < 1 блока, jesus (хождение по
    воде — исключение для жидкостей), точная симуляция как в Grim.

### 10. Fastbreak / nuker
Время копания проверяется (`dig.go:82`, допуск 70%), но:
- нет лимита на количество блоков в тик (instant-блоки шерсти/стекла можно
  ломать десятками за пакетную очередь);
- `startDig` по новому блоку молча сбрасывает старый — нормально, но нет
  проверки, что игрок смотрит на блок.
- **Фикс:** reach (п.7) + лимит ~ 1 instant-break на тик + проверка угла
  (направление взгляда vs. центр блока, допуск ~60°).

### 11. Scaffold / fastplace
Нет лимита частоты установки и проверки, что кликнутая грань видна.
- **Фикс:** ≤ ~1 установки за тик (vanilla-клиент — 4 тика задержки между
  правыми кликами, кроме быстрого ручного кликанья), проверка, что грань
  `face` обращена к глазам игрока, курсор (`cursor x/y/z`, сейчас
  выбрасывается) в [0,1].

### 12. Autoclicker / killaura (эвристики)
В 1.8-режиме (`PvP18`) кулдауна нет — CPS ничем не ограничен.
- **Фикс:** лимит атак ≤ 20/с жёстко; статистика CPS и дисперсии интервалов;
  угол между взглядом и жертвой (> 90° — явная аура); атака без
  предшествующего `SwingArm` в том же тике.

### 13. Компенсация задержки
Для честных reach/velocity нужна история позиций каждого игрока (кольцевой
буфер ~1 с по тикам) и пинг атакующего: reach проверяется против позиции
жертвы «пинг назад». Для velocity (anti-knockback) — Ping/Pong (Cb 0x33 /
Sb 0x23) вокруг Set Entity Velocity и сравнение следующего движения.

## P2 — протокол и мелочи

14. ✅ **Set Held Item** (`handler_play.go:472`) — нет проверки 0..8. Отрицательное
    значение адресует main-inventory (`inv.held` → слот 36+n): «держать»
    меч из рюкзака. Фикс: вне диапазона — игнор + нарушение.
15. ✅ **Keep-alive** (`keep_alive.go:96`) — ответ с неверным id молча
    игнорировался; теперь флаг `badpackets.keepalive`. Также не замеряется пинг (нужен для п.13).
16. ✅ **Pitch** не ограничен ±90 (`SetRot` проверяет только finite). Vanilla
    кикает за |pitch| > 90 — индикатор чита.
17. ✅ **Rate limit пакетов**: нет общего лимита пакетов/с на соединение
    (vanilla-клиент держится < ~100/с). Флуд Interact/UseItem/Click жжёт CPU
    и рассылки всем игрокам. Фикс: токен-бакет, кик при > 500/с.
18. ✅ **Sprint** (`handler_play.go:387`) — флаг от клиента без проверки
    голода/движения вперёд/слепоты; влияет на нокбек (`applyKnockback`).
    **Сделано:** удар с бонусом спринта заканчивает спринт атакующего на
    сервере (как vanilla `Player.attack`) — KeepSprint больше не даёт
    лишнего нокбека; бонус не даётся, если игрок крадётся, ослеплён или
    ест/тянет лук (`sprintHit`). Голода сервер не моделирует, «спринт назад»
    — задача симуляции движения (#9).
19. ✅ **Chat/command flood** — есть модератор, но стоит проверить, что
    команды тоже лимитируются.
    **Сделано:** `acceptChat` для чата и команд — символы, которых нет в
    vanilla-чате (`§`, управляющие, DEL) или > 256 символов → флаг
    `badpackets.chat` + отброс (иначе `§`/`\n` подделывали цветные и
    многострочные «системные» строки); лимит спама как в vanilla
    (`chatSpamTickCount`: всплеск 10, затем 1/с) → кик, опы освобождены.
20. ✅ **Drop flood** — Q/ctrl+Q и клики спавнят item-сущности; лимит частоты.
    **Сделано:** бюджет 20 выбросов/с (всплеск 40) на Q, ctrl+Q и броски
    из окон; сверх — отказ с ресинком слота/окна.

| Компонент | Что даёт | Где используется |
|---|---|---|
| `Teleports` | каждый Sync Position получает id; пока клиент не подтвердил — его движение игнорируется (как vanilla) | все телепорты через `sendSyncPlayerPosition` / `sendSetback` |
| `Transactions` | Ping (Cb 0x32) / Pong (Sb 0x20): по Pong известно, какой тик сервера клиент уже видел, + RTT; колбэк на подтверждение | `Server.TickTransactions` — Ping каждый тик (вкл. в `main.go`); `c.sendTransaction(cb)` для событий (нокбек и т.п. — следующий шаг) |
| `History` | позиция игрока за последние 64 тика | `Instance.anticheatTick`; основа lag-compensated reach |
| `Violations` | VL по чекам с затуханием 0.1/с + последние 32 причины | `c.flag(check, detail)` — пока только лог |
| `RateLimiter` | бюджет пакетов 400/с, всплеск 800 | превышение → кик |
| `Sprinting`/`Sneaking` | ввод клиента из Player Command | нокбек, высота глаз в истории |

Проверки протокола, включённые сейчас (флаг, пакет отбрасывается):
`badpackets.teleport` (чужой id подтверждения), `badpackets.transaction`
(Pong без Ping или вне порядка), `badpackets.keepalive` (чужой id),
`badpackets.helditem` (слот вне 0..8 — закрывает п.14), `badpackets.pitch`
(|pitch| > 90 — п.16), `badpackets.command` (Player Command для чужой
сущности). Флуд пакетов — кик (п.17). Не отвечает на 200 Ping подряд — кик.

## Архитектура (предложение)

Отдельный пакет `anticheat/` без зависимости от `server/` (как `game/`):

```
anticheat/
  check.go       // type Check interface; Violation{Check, VL, Detail}
  tracker.go     // per-player: VL с затуханием, история позиций, CPS, timer-баланс
  movement.go    // speed, fly, timer, phase (чистые функции над снапшотами)
  combat.go      // reach, angle, cps
  world.go       // reach/angle/rate для dig/place
```

- `server/` вызывает чеки из обработчиков и решает реакцию:
  **cancel** (откат действия) → **setback** (Sync Position) → при VL выше
  порога **детект** → наказание по лестнице статусов (см. ниже).
- Пороги и включение — env-переменные, как `PVP_VERSION`; режим
  `ANTICHEAT=log` (только логировать) для подбора порогов без ложных киков.
- Нарушения — в `slog.Warn` + метрика в `metrics.go`; опционально уведомление
  операторам в чат.
- Оп-игроки и creative освобождены от movement/reach (как в vanilla).

## Наказания: лестница статусов

Решение владельца проекта (2026-10-28). У каждого игрока есть
**античит-статус**. Он хранится постоянно, переживает перезаходы и рестарты
и привязан к аккаунту (UUID / строка в `players`). **Детект** — это нарушение,
у которого VL перешёл порог кика. Отдельные откаты (cancel/setback) статус
не повышают.

| Статус | Название | Что происходит при детекте на этом статусе |
|---|---|---|
| 0 | `clean` | → статус 1, **кик** («подозрение на читы») |
| 1 | `suspicious` | → статус 2, **бан на 1 день** |
| 2 | `banned_1d` | → статус 3, **бан на 3 дня** |
| 3 | `banned_3d` | → статус 4, **бан на 7 дней** |
| 4 | `banned_7d` | → статус 5 (`max`), **бан на 1 день** + уведомление админов |
| 5 | `max` | автоматического бана нет: **кик** + уведомление; срок бана решает админ (`/ban`) |

- Повышается ровно на одну ступень за один детект. Несколько детектов за
  одну сессию дают одну ступень, потому что после первого игрок уже кикнут
  или забанен.
- Пример: игрока поймали, он получил кик (статус 1). Он перезашёл, и его
  снова поймали на чём угодно, не обязательно на том же чите. Получает бан
  на 1 день (статус 2). Дальше 3 дня, потом неделя, потом статус `max`
  с баном на 1 день и уведомлением админов.
- Баны выдаются через существующий `Server.Bans` (`ban.Store`) с `expires`
  и причиной, поэтому `/unban` и проверка при логине работают как сейчас.
- Режим `ANTICHEAT=log` не наказывает: детекты только пишутся в журнал,
  статус не меняется.

### Журнал наказаний

Каждое наказание (кик, бан, переход в `max`) пишется отдельной записью.
Причины обязательны:

- игрок (UUID + ник на момент наказания), время, инстанс/режим (`bw-3`, хаб…);
- статус до и после, действие (`kick` / `ban` + срок, с пометкой `flag_admin` при переходе в `max`);
- **причины**: список чеков, которые привели к детекту: имя чека (`reach`,
  `fly`, `inventory.dupe`…), итоговый VL и детали последних нарушений
  (например «reach 5.8 > 3.5 по игроку X», «+64 diamond в клике окна 0»);
- кто наказал: `anticheat` или ник админа (при ручном бане со статуса `max`).

Хранение: таблица Postgres `anticheat_punishments` (+ колонка статуса у
игрока, миграция в `store/migrations/`). Под `STORAGE=memory` используется
JSON-файл по аналогии с `banlist.json`. Для админов нужна команда просмотра,
например `/ac info <ник>` (статус + история с причинами), и `/ac reset <ник>`.

### Реализация (сделано 2026-10-28)

- Лестница — `anticheat.Escalate` (`anticheat/punish.go`), ровно по таблице
  выше. Детект — VL чека ≥ `anticheat.Threshold(check)`: по умолчанию 2.5,
  т.е. три флага за ~5 с (VL убывает 0.1/с); `anticheat.Thresholds` —
  переопределения для будущих эвристик (reach, speed).
- Один детект за сессию двигает лестницу на одну ступень
  (`State.Detected`). Порядок: бан в `Server.Bans` (с причиной и сроком) →
  запись в журнал → уведомление онлайн-операторов (на `max`) → кик. Игрок
  видит общее «suspected cheating» без имени чека — подробности только
  админам. Если журнал недоступен — кик без повышения статуса.
- Хранилище — `anticheat.Store` (`Server.AnticheatLog`): Postgres
  `store.AnticheatRepo` — таблицы `anticheat_status` (текущий статус, по
  UUID) и `anticheat_punishments` (журнал, причины в JSONB), миграция
  `0004_anticheat`; при `STORAGE=memory` — `anticheat.FileStore` на
  `ANTICHEAT_FILE` (по умолчанию `anticheat.json`, `off` = только RAM).
- Причины в каждой записи — последние 32 флага соединения (чек, детали,
  VL, время).
- **Включение: `ANTICHEAT=enforce`.** По умолчанию (`log`) детекты только
  пишутся в лог сервера — до проверки чеков на реальных клиентах.
- Команды операторов: `/ac info <ник>` (статус + 10 последних записей с
  причинами; офлайн-игрок ищется по нику в журнале), `/ac reset <ник>
  [причина]` (статус → clean, запись `reset` с ником админа). Ручной `/ban`
  игрока на статусе `max` пишется в журнал с причиной админа.

**Открытые вопросы** (сейчас реализовано консервативно, легко поменять):
- Снижается ли статус со временем (например через N дней без детектов)?
  Сейчас — только вручную через `/ac reset`.
- Игрок в статусе `max`: сейчас пускается на сервер (после бана на день) и
  кикается с уведомлением при каждом детекте.
